About the Pipeline

This repository contains scripts, documentation, training materials, and example resources for whole-genome sequencing (WGS) copy number variation (CNV) analysis. This pipeline produced the results published in this paper https://doi.org/10.1371/journal.pone.0353468

The workflow integrates CNV detection methods including:

  • CNVnator
  • CNVcaller
  • LUMPY Express
  • CNV merging and annotation

2. CNV Detection

This step identifies copy number variations from whole-genome sequencing data using CNV calling algorithms. Copy number variations (CNVs) are genomic alterations involving deletions or duplications of DNA segments. There are four main methods of detecting CNVs with NGS data:

  • Read-Pair (RP)
  • Split-Read (SR)
  • Read-Depth (RD)
  • Assembly (AS)

Each of these four methods specializes in detecting a specific form or size range of CNV, resulting in a trade-off in breakpoint accuracy. None of these methodologies is perfect; each brings advantages and disadvantages. To address this, many labs combine different methods, such as read-depths with read-pairs, or read-depths with split-reads, to achieve a more holistic analysis.

Methodology

A read depth approach was used to detect copy number variations. To increase the reliability of CNV detection, CNVnator and CNVcaller were used. CNVnator utilizes fixed-bin read-depth histograms for sensitive detection of CNVs, whereas CNVcaller applies population-based normalization and segmentation models to improve breakpoint resolution and reduce false positives. However, I also included LUMPY scripts incase you want to use both read depth tools combined with split reads tools.

CNVnator

CNV detection using CNVnator was carried out for the autosomal chromosomes only, using a bin size of 100 bp. Depending on the coverage you have in your data you might need to use a different bin size. The following steps were run; CNVnator -tree, CNVnator -his, CNVnator -stat, CNVnator -partition and CNVnator -call and identification of CNV occurrence in the preset window was done. The software calls CNVs per individual, and to enhance the CNV prediction quality control, raw CNVs were filtered by retaining only those with q0 < 0.5, size >1kb and p-value<0.01 based on t-test statistics. A q0 filter removes any CNV calls with q0 > 0.5 and the metric represents the fraction of reads within a region that have zero mapping quality which means reads with multiple mapping locations in the genome. This is crucial because regions with q0 > 0.5 are likely enriched for ambiguously mapped reads that potentially lead to false positive CNV detection. To compare the results from CNVcaller, individual CNVs were merged using 50% reciprocal overlap to create population-based CNVRs.

CNVcaller

CNVcaller is a population-based CNV detection software that analyses population sequencing data across individuals simultaneously rather than independently. This approach leverages on using population-level read depth information to perform local depth normalization and segmentation across samples (adaptive binning instead of fixed bin size used in CNVnator), resulting in reduced false positives and improved breakpoint accuracy. Initially, the reference genome used in the present study (NIAB_ARS_BosIndicus_Tharparkar_1.0) lacked the duplicated window record files required for CNVcaller's absolute number correction. Hence, custom duplicated window record files were generated following the official CNVcaller pipeline. Briefly, the reference database for Bos indicus was created using NIAB_ARS_BosIndicus_Tharparkar_1.0 which was segmented into k-mer sequences (overlapping windows) using the CNVcaller script 0.1.Kmer_Generate.py with a recommended window size of 800 bp to optimize CNV detection and boundary resolution. The resulting k-mer FASTA file was then aligned back to the reference genome using BLASR after constructing the suffix array index with sawriter. BLASR alignment was performed using the parameters recommended in the CNVcaller documentation for sensitive k-mer mapping. Finally, duplicated window record files were generated from the BLASR alignment output using 0.2.Kmer_Link.py, producing the genome-wide window linkage file required for downstream CNV analysis. The resulting reference database and duplicated window files were then used for CNV detection in CNVcaller. The custom scripts used for generating the CNVcaller duplicated window files and reference database are available on GitHub. CNVcaller calculated the GC-corrected normalized read depth for each sample to standardize the copy number in each window and classify different genotypes. The following CNVcaller parameters were used for filtering: -f 0.1 to set the frequency threshold of 10% for downstream analysis, -h 3 to retain CNVs shared in at least three samples, and -r 0.5 to set the minimum reciprocal overlap to be 50% between CNVs for merging or creating population-based CNVRs. Additionally, CNVs with a Silhouette score of >0.5 and those located in unplaced scaffolds were excluded from further analysis. It is important to note that the CNVcaller filtering thresholds (-f 0.1, -h 3) used in this study prioritize high confidence CNVRs and might have reduced sensitivity to rare or low frequency variants.

CNVcaller.sh · post_qc_filter_cnvcaller.sh

LUMPY Express

LUMPY Express identifies structural variants, including CNVs, using discordant read-pair and split-read evidence. This provides breakpoint-level resolution that complements the read-depth approaches above. Genotyping and variant typing were performed on the raw LUMPY calls as a post-processing step.

lumpy.sh · lumpy_genotype.sh · svtype.py

3. CNV Integration

Once you have results from two or three software, the most important part is to integrate the results. In this workflow, you will learn how to merge output from two software (CNVcaller and CNVnator). If you need a script for merging three software, check out merging_all3_tools.sh.

This step merges CNV calls produced by different detection tools into a single, consolidated set of copy number variant regions (CNVRs), reducing redundancy and improving confidence in the final call set. Please note you might need to carry out a sensitivity analysis depending on the parameters you choose for the merging.

4. Annotation

Once CNVs have been detected and merged into a consolidated call set, the final step is to annotate each variant with genomic context, such as overlapping genes, regulatory elements, known functional regions, and trait-associated QTLs.

Gene Annotation (ANNOVAR)

Gene-level annotation was carried out using ANNOVAR, guided by a chromosome mapping file to match variant coordinates to the reference genome build used in this study.

ANNOVAR.sh · annotation_ANNOVAR/ · chrom_map.txt

QTL Annotation

Candidate CNV regions (CNVRs) were also annotated against the AnimalQTLdb to identify overlaps with known trait-associated QTLs. CNVR coordinates and the QTL database were converted to BED format, sorted, and intersected using bedtools intersect to find overlapping regions. Because AnimalQTLdb often contains multiple entries for the same QTL name (differing only by ID), a filtering step was applied to reduce redundancy: QTLs of the same trait falling within the same CNVR were merged into a single row, while QTLs of the same trait located in different CNVRs, or on different chromosomes, were retained as separate rows.
